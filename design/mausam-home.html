Mausam, rebuilt around one person.

Today every Mausam user opens the same homepage. This design reflows it around the one to three personas a user actually picks — and proves the two things a weather app for severe warnings cannot get wrong: legibility on every sky, and a reason for every card.

Glass, and what happens when it costs too much

One surface recipe, two polarities, one fallback. The fallback isn’t a downgrade path to argue about later — it’s specified now, because a blurred backdrop on a low-end Android GPU is exactly where the current app already loses frames.

Type

Google Sans Flex carries the interface at a single variable weight axis; Google Sans Code handles anything that reads as an instrument — station names, units, IST timestamps, warning validity. Numerals are tabular everywhere they stack.

Motion

Four named springs, each with a job. Nothing eases linearly, nothing cuts. Tap a track to play the curve; every value below is the Framer Motion config, not an approximation of one.

Why each card is there

Score = persona weight (order picked) + urgency boost from the live reading. No model, no embedding — a judge asking “why is this card here” gets the sentence in the last column, and the app shows the same sentence under Why.
